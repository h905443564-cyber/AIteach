# 贵州版 · 通联智多星培训材料 · 版本管理规范

> 本文件定义「面向**贵州分公司**」这份培训材料（简称**贵州版**）的归档规范与工作流程。
> 广东版规范见 `智多星培训0903v1/outputs/versions/广东版_版本管理规范.md`。

---

## 一、目录结构

```
智多星培训0910贵州版/
├── outputs/                                          # 【工作区】当前最新版本，持续迭代
│   ├── 贵州版_通联智多星平台培训_设计稿.html            # 培训材料（HTML 演示稿，待生成）
│   ├── 贵州版_培训讲稿.md                              # 配套讲稿（待生成）
│   ├── 素材/                                         # 本版本专属图片素材
│   ├── versions/                                     # 【归档区】历史定稿版本
│   │   ├── 贵州版_版本管理规范.md                      # 本文件
│   │   ├── 贵州版_版本记录.md                          # 总索引
│   │   ├── 贵州版_核心大纲.md                          # 核心大纲（滚动更新至最新版）
│   │   └── v<日期>_<版本名>/                           # 每个定稿版本一个快照目录
│   │       ├── 贵州版_v<日期>_修订记录.md
│   │       ├── 贵州版_v<日期>_核心大纲.md
│   │       ├── 贵州版_v<日期>_培训材料.html
│   │       └── 贵州版_v<日期>_培训讲稿.md
```

---

## 二、每次版本定稿后的归档动作（标准流程）

1. **快照培训材料** → `versions/v<日期>_<版本名>/贵州版_v<日期>_培训材料.html`
2. **快照讲稿** → 同目录 `贵州版_v<日期>_培训讲稿.md`
3. **写修订记录** → 同目录 `贵州版_v<日期>_修订记录.md`（逐条说明页面、内容、原因）
4. **更新核心大纲** → 同目录 `贵州版_v<日期>_核心大纲.md`，并同步 `versions/贵州版_核心大纲.md`
5. **更新总索引** → `versions/贵州版_版本记录.md` 追加版本行与修订明细
6. **保留工作区** → `outputs/` 继续作为下一轮迭代工作区

---

## 三、命名规范

> **核心规则：所有材料文件名以「分支前缀」开头，归档快照再带版本号。**
> 目的是避免与广东版（`智多星培训0903v1/`）出现同名文件，无法区分。

| 类型 | 命名格式 | 示例 |
|------|---------|------|
| 分支前缀 | `贵州版_` / `广东版_` | `贵州版_核心大纲.md` |
| 版本目录 | `v<YYYYMMDD>_<版本名>` | `v20260910_初版框架` |
| 归档文件 | `<分支前缀>_v<YYYYMMDD>_<类型>.<ext>` | `贵州版_v20260910_培训材料.html` |

---

## 四、与广东版的关系

- **独立项目**：本份材料面向贵州分公司，拥有独立的工作区与版本归档，不覆盖广东版。
- **素材复用**：需要广东版的图片素材时，从 `智多星培训0903v1/outputs/` 复制到本目录 `outputs/素材/`，
  避免跨目录引用导致的路径失效。
- **结构参考**：广东版结构见 `智多星培训0903v1/outputs/versions/广东版_核心大纲.md`。

---

## 五、版本还原方法

1. 从 `outputs/versions/v<日期>_<版本名>/` 中取出 `贵州版_v<日期>_培训材料.html`
2. 复制到 `outputs/` 并重命名为 `贵州版_通联智多星平台培训_设计稿.html`
3. 同理取出 `贵州版_v<日期>_培训讲稿.md` 替换 `outputs/` 下对应讲稿
