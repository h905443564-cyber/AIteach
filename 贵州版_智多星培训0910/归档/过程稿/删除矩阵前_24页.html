场景一 · 交易查询与差错处理
收单与网络支付最高频的一类求助 —— 过去要逐个系统翻
📌 场景是什么
商户最常说的两句话：「钱没到账」「这笔交易失败了」。过去要分别登录收付通、收银宝、查秒到记录、再翻业务规则，来回对口径。
🧪 我们做了什么尝试（仅用现有能力）
数据：S 收付通（交易查询 / 统计 / 诊断）、Y 收银宝（交易统计）、O 商户侧（交易详情 / 结算 / 秒到）
知识：K 三级知识库（差错处理口径、业务规则，带引用溯源）
生成：G2 诊断报告
🗨️ 典型问法与编排链
「商户号 XXXXX 说昨天那笔钱没到账」
→ 结算记录 → 交易详情 → 秒到记录 → 结算配置 → 知识库规则
一次问清，直接给结论与依据。
🛡️ 权限边界（明确不做）
目前只做查询和指引：退款、调账、改结算配置这些涉及资金的动作，还是走原有工单、由人工复核。
🤝 欢迎补充与拓展
贵州高频的差错类型与本地处理口径，可录入部门知识库 —— 供得越多，结论越贴合本地。
场景二 · 商户与终端管理
入网、资料变更、门店终端、渠道报备 —— 资料散在多个系统
📌 场景是什么
商户入网建档、换结算卡、更新证件、查门店与终端、跟进渠道报备进度，这些资料分散在不同系统里。
🧪 我们做了什么尝试（仅用现有能力）
数据：S 收付通（商户档案）、Y 收银宝（商户 / 门店 / 终端、渠道报备、合规合同、套餐补贴、卡 bin）
知识：K 三级知识库（入网材料清单、变更流程）
对商户：O 结算信息与套餐余量
🗨️ 典型问法与编排链
「这家商户要换结算卡，要走什么流程」
→ 商户档案 → 合规合同状态 → 套餐余量 → 自助变更分步指引
🛡️ 权限边界（明确不做）
资料变更目前还是不给代为提交：只给分步指引，由商户在好老板 APP 自助完成，或由运营按现有流程处理。
🤝 欢迎补充与拓展
贵州各城市的入网材料差异、本地终端与码牌管理经验 —— 沉淀进部门知识库即可复用。
场景三 · 接入联调与技术支持
接口对接、联调报错、报文分析 —— 对应网络支付类业务
📌 场景是什么
商户或渠道接入时，最容易卡在接口报错与联调排障上：报错码看不懂、报文拿不到、文档找不到对应章节。
🧪 我们做了什么尝试（仅用现有能力）
数据：S 收付通（联调日志、原始报文）、Y 收银宝（卡 bin、渠道报备）
技能：研发智擎 AI 技能包（接口对接指引、示例代码、报错定位）
知识：K 文档中心与接口文档
🗨️ 典型问法与编排链
「接口返回「验证签名失败」怎么排查」
→ 联调日志 → 原始报文 → 接口文档 / 技能包 → 报错原因与修复建议
🛡️ 权限边界（明确不做）
不代改商户侧代码；结论是建议，最终由技术同学确认后再动生产环境。
🤝 欢迎补充与拓展
贵州本地的接入案例、常见报错与解法，可沉淀为技能包，团队共用、新人也能直接上手。
