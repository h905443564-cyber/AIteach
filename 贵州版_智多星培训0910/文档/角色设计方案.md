> ⚠️ **本方案已被 2026-09-16 的方向调整取代**：演示稿 PART 02 已由「按角色」改为「**按业务场景**」组织。`r

> 目标：把原子化的能力清单（47 个业务 MCP Tool + 三级知识库 + 生成/编排/多端能力），

## 二、角色总览（6 个核心角色）

按「对内 / 对外」×「业务环节」两个维度切分，避免出现"一个角色什么都能干、什么都不精"。

| # | 角色名 | 代号 | 服务对象 | 一句话定位 | 数据面 | 优先级 |
|---|---|---|---|---|---|---|
| R1 | **运营支持官** | Ops-Copilot | 分公司运营、客服支撑 | 商户问题"一句话查清、一次说透" | 对内 | P0 |
| R2 | **接入技术官** | Tech-Copilot | 技术对接、开发、实施 | 联调排障的第一响应人 | 对内+对外 | P0 |
| R3 | **商户服务官** | 发仔·客服 | 商户（老板/店长/收银） | 到账、结算、套餐问题的自助答案 | 对外 | P0 |
| R4 | **商户经营官** | Biz-Advisor | 商户经营者、市场回访 | 会看账、会算账、会给建议的生意参谋 | 对外 | P1 |
| R5 | **市场拓展官** | Sales-Copilot | 市场/销售/拓展人员 | 懂产品、懂竞品、会报价的展业军师 | 对内 | P1 |
| R6 | **风控合规官** | Risk-Sentinel | 风控、合规、财务 | 限额、合规、异常经营的扫描雷达 | 对内 | P1 |
| R7 | **知识运营官**（支撑角色） | KB-Curator | 分公司知识管理员、培训 | 让知识库"活起来"的管家 | 知识侧 | P2 |

> 门面统一为「发仔」，不同角色=发仔的不同"岗位皮肤"，用户无需理解底层 Agent 差异。

## 三、角色卡（能力组合 + 场景 + 边界）

### R1 · 运营支持官（Ops-Copilot）

- **定位**：运营同学的手边"百事通"，把"翻 5 个系统、问 3 个人"压缩成"一句话"。
- **入口**：企业微信 / PC 网页（forInner=true）
- **装配能力**
  - 知识：K1 公共 + K2 部门 + K5 溯源（主营）
  - 数据：S1 S3 S4 S5 S6 S7 S8（收付通）｜ Y1 Y3 Y5 Y7 Y8 Y9 Y10 Y11 Y12（收银宝）
  - 生成：G2 单商户诊断报告、G4 话术/FAQ
  - 平台：P1 多端、P3 权限审计
- **高频场景**
  1. "商户说钱没到账" → Y9/S4 结算记录 + Y10 交易详情 + O5（秒到）→ 给出"已结算/在途/失败原因"结论
  2. "这笔交易为什么失败" → S5/S6 或 Y10 → 交易诊断 + 失败原因归类 + 处置建议
  3. "帮我看看这个商户整体情况" → S8 / Y12 商户综合分析 → 一屏画像（产品、近期交易、收益）
  4. "这个码牌/终端是哪个商户的" → Y3 码牌反查 → 商户号 + 门店
  5. "结算规则是什么 / 这个产品怎么开通" → K1 知识库问答（带出处）
- **权限边界**：只读；对内 Tool 需 `forInner + userid`；单次结算/余额查询 ≤15 天；不触碰其他分公司的部门知识库。
- **明确不做**：不做风控定性结论（转 R6）、不改任何配置（只读）、不承诺资金时效以外的业务承诺。
- **成效指标**：单问题处理时长 ↓、一次解决率 ↑、人工转派率 ↓。

### R2 · 接入技术官（Tech-Copilot）

- **定位**：商户/渠道接入与联调排障的第一响应人，"把报文甩给它就能看出问题"。
- **入口**：企业微信 / PC 网页 / 开发者页面（对内+对外）
- **装配能力**
  - 知识：K1（接口文档、错误码、接入 SOP）+ K5 溯源
  - 数据：S9 / Y13 联调日志与原始报文（核心）｜ S5 S6 / Y10 交易详情与诊断 ｜ Y5 渠道报备 ｜ Y14 卡 bin ｜ Y1 Y3 商户与终端
  - 生成：G4 排障结论模板、接口示例生成
  - 平台：P2 MCP 开放接入（引导商户/三方系统自助接入）
- **高频场景**
  1. "回调没收到" → Y13/S9（app=notify）→ 通知侧日志 + 是否发出、响应码
  2. "这单报错 ERxxx 是什么意思" → 日志 + 知识库错误码 → 原因 + 修改建议
  3. "这个渠道报备到哪一步了" → Y5 渠道报备状态、渠道商户号、认证状态、微信参数
  4. "这张卡是哪家银行、贷记还是借记" → Y14 卡 bin
  5. "我要接入，给我流程和示例" → K1 接入文档 + 样例报文 + 常见坑
- **权限边界**：日志查询按 `reqSn/traceid + datehour` 定位；报文含敏感字段需脱敏展示；对外场景只能查`自己商户上下文`的数据。
- **明确不做**：不下"系统故障"的定性（只给证据 + 建议升级）、不修改生产配置、不复述未经知识库确认的接口约定。

### R3 · 商户服务官（发仔·智能客服）

- **定位**：面向商户的自助服务门面，7×24 回答"我的钱、我的单、我的套餐"。
- **入口**：好老板 APP / H5 / 智能客服 / QQ 群机器人（对外·上下文透传）
- **装配能力**
  - 数据：O1 O2 O3 O4 O5 O6（全部对外 Tool）
  - 知识：K1 对外知识库（商户自助指南、常见问题）
  - 生成：G4 自然语言答复（不抛术语、不抛字段名）
- **高频场景**
  1. "钱到账了吗" → O5 结算记录 / 秒到记录 → "已到账/处理中/失败原因"
  2. "这笔手续费怎么没走套餐" → O4 套餐余量 + O6 交易详情 → 套餐类型/有效期/适用产品/额度 逐项核对
  3. "为什么没实时到账" → O4 结算配置（是否开通秒到）+ O5
  4. "我的码牌/终端状态" → O4 终端查询
  5. "这个月生意怎么样" → O3 / O6 经营报告（简版，含建议）
- **权限边界**：严格上下文透传，**只能看登录商户自己的数据**；不做跨商户比对；不展示内部风控参数与成本信息。
- **明确不做**：不承诺赔付/时效、不处理投诉定性、复杂争议转人工工单（附已取数据，减少重复询问）。

### R4 · 商户经营官（Biz-Advisor）

- **定位**：商户的"生意参谋"——会看账、会算账、会提建议，也是市场回访商户时的共创工具。
- **入口**：好老板 APP / PC（对外为主，内部代查需授权）
- **装配能力**
  - 数据：O3 / O6 经营报告（核心）｜ O2 交易统计（可切门店/终端维度）｜ O1 余额趋势 ｜ O4 套餐与营销活动
  - 生成：G2 经营诊断报告（含图表）｜ G1 营销文案/广告语（音箱播报）
  - 知识：K1 行业经营建议、产品适配规则
- **高频场景**
  1. "本月经营报告" → O3/O6 → 笔数/金额/成功率/时段分布 + 三条可执行建议
  2. "哪天/哪个门店掉量了" → O2 按门店/终端统计 → 定位下滑点 + 原因假设
  3. "套餐还剩多少，够用到月底吗" → O4 套餐余量 + 近 15 天消耗 → 测算可用天数
  4. "帮我写个促销语播报到云音箱" → G1 → 生成 + 配置播报
  5. "要不要上 XX 产品" → K1 产品知识 + 该商户交易结构 → 适配性建议与收益测算
- **权限边界**：仅本商户数据；经营建议须标注"基于近 N 天数据测算"；不提供竞品商户的对标数据。
- **明确不做**：不做投资/经营保证、不输出其他商户数据、不替代人工签署类动作。

### R5 · 市场拓展官（Sales-Copilot）

- **定位**：市场/销售/拓展的"展业军师"——懂产品、懂竞品、会报价、会写方案。
- **入口**：企业微信 / PC（对内）
- **装配能力**
  - 知识：K1 产品手册/费率政策/入网资料 + K2 分公司政策 + K3 个人客户档案 + K5 溯源（主营）
  - 数据：Y1 按名称查商户（拓客查重/背景核实）｜ S8 / Y12 商户综合分析（存量挖掘）｜ Y6 营销活动 ｜ Y7 套餐/补贴 ｜ S2/Y4 限额（回答"能跑多少量"）
  - 生成：G1 宣传文案 ｜ G4 方案/话术/FAQ/竞品对比
- **高频场景**
  1. "这个客户适合什么产品" → 客户背景 + K1 产品适配 → 推荐 2~3 个产品 + 理由 + 费率区间
  2. "入网要什么材料" → K1 知识库 → 材料清单 + 常见驳回点（带出处）
  3. "XX 竞品和我们比怎么样" → K1 竞品知识 → 对比表（只讲公开信息 + 我司优势）
  4. "这个存量商户还有提升空间吗" → S8/Y12 综合分析 → 增量机会点
  5. "帮我写一段拜访开场白/群公告" → G1/G4 → 成稿
- **权限边界**：可查对内商户档案但**只用于业务拓展**，遵循最小必要；不得批量导出商户清单；对外材料须过合规口径。
- **明确不做**：不给未审批的费率承诺、不做违规补贴宣传、不替代合同/报价单正式流程。

### R6 · 风控合规官（Risk-Sentinel）

- **定位**：风控/合规/财务的"扫描雷达"——把限额、合规、异常经营从"人找数据"变成"数据找人"。
- **入口**：PC 网页（对内，权限收紧）
- **装配能力**
  - 数据：S2 / Y4 风控限额（是否设限、单笔/单日上限）｜ Y6 合规审核进度 ｜ S7 / Y11 交易统计 ｜ S8 / Y12 综合分析 ｜ S3 / Y8 余额与冻结 ｜ S6 交易诊断
  - 生成：G3 批量风险扫描报告（成功率异常、零成功有成本、成本倒挂、集中度、跨行占比、归属缺失等规则）+ 聚集分析（按拓展人/维护人/分公司）
  - 知识：K1 风控与合规制度
- **高频场景**
  1. "这个商户限额设了吗" → S2/Y4 → 未设限/超限项高亮告警
  2. "合规审核到哪一步" → Y6 → 进度 + 卡点 + 下一步动作
  3. "最近哪些商户异常" → S7/Y11 + G3 → 风险清单 + 规则命中说明 + 建议处置
  4. "有没有倒挂/亏损条线" → G3 聚集分析 → 按拓展人/维护人聚类的风险条线
  5. "这单为什么被拒" → S6 诊断 + 限额比对 → 命中哪个限额/风控项
- **权限边界**：对内高敏，需白名单 userid + 审计留痕；仅输出"风险线索与建议"，**不下发处置动作**；对外绝不可见。
- **明确不做**：不直接冻结/限额变更、不做合规最终裁定、不向商户侧透露风控阈值。

### R7 · 知识运营官（KB-Curator，支撑角色）

- **定位**：让知识库"活起来"的管家——管入库、管质量、管更新，是其他 6 个角色的"弹药供给"。
- **装配能力**：K4 文档上传/URL 抓取 ｜ K1/K2 知识组管理 ｜ P3 权限与可见范围 ｜ P4 质量评估与回归用例 ｜ G4 FAQ/题库生成
- **高频场景**：新政策批量入库并生成 FAQ、失效文档巡检、知识命中率与 Badcase 归因、按角色维护专属知识组。
- **边界**：涉密文件不入库；敏感内容自动拦截；知识变更留痕。
- **优先级**：P2（但建议与 P0 角色同步起步，否则角色会"无米下锅"）。

## 五、权限与数据边界（硬约束）

| 维度 | 对内角色（R1/R2/R5/R6/R7） | 对外角色（R3/R4） |
|---|---|---|
| 调用方式 | `chatBizOptions.forInner=true` + `userid`（须在 appkey `binduserids` 内） | 上下文透传商户身份，无 cusid 入参 |
| 可见 Tool | `inner_*` 对内 Tool + 对外 Tool 的受控子集 | 仅 `sft_cus*`、`syb_cus*` 对外 Tool |
| 数据范围 | 全量商户（按角色最小必要裁剪） | 仅登录商户自身 |
| 敏感信息 | 成本/风控阈值按角色分级，R6 最高 | 不可见内部成本与风控参数 |
| 时间窗 | 结算/余额/统计单次 ≤15 天，超窗自动拆片 | 同上 |
| 审计 | 全量留痕 + 敏感拦截 | 留痕 |
| 红线 | 涉密文件不入库；只读不写；不下发业务处置动作 | 不承诺赔付/时效；争议转人工 |

## 六、角色路由与协作

1. **统一门面**：用户只对话"发仔"，由路由层判定角色（显式：用户选岗位 / 隐式：意图识别 + 身份 + 入口）。
2. **角色内编排**：一次提问可串多个 Tool（例 R1"钱没到账"= 结算记录 → 交易详情 → 秒到记录 → 知识库规则），编排由平台侧完成，本地只做分析。
3. **角色间转派**：
   - 命中限额/合规疑点 → R1 转 R6（带上下文，不重复取数）
   - 需要看报文/回调 → R1、R3 转 R2
   - 商户要深度经营建议 → R3 转 R4
   - 无法确权/投诉定性 → 转人工工单，附上已取数据
4. **取数与分析分离**：角色只负责"问清楚 + 取准数"，计算、判断、结论由本地分析引擎产出，保证口径可复核。

## 七、角色装配模板（落地用）

新建角色 = 填这张卡，未填项不允许上线：

```
角色名 / 代号 / 一句话定位
服务对象 + 主入口
能力白名单：  知识组[]  +  Tool 白名单[]  +  生成能力[]
典型问法：    5~10 条（含期望调用链与输出格式）
输出规范：    结论先行 → 数据支撑 → 处置建议 → 数据来源/口径
边界：        不做 X / 不查 Y / 不确定时转 Z
权限：        对内? userid 范围?  数据时间窗?  脱敏规则?
评测：        用例集 + 通过率目标 + Badcase 回归
```
