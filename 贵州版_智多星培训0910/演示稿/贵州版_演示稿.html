知识问答与培训赋能
找产品参数、找接口文档、找版本记录 —— 答案带引用溯源，打开原文就能核对
📌 场景是什么
开发要找接口文档、运营同事查常用Q&A、市场同事找产品手册 —— 过去要么翻文档中心，要么问老同事。
现在直接问发仔，答案附带原文出处，点开就能核对原文。
🧵 这个场景是怎么搭起来的 提词 + 接口 + 模型
① 提词
问清知识类型（制度 / 产品 / 流程）与适用场景，缺信息就追问，避免泛泛而谈
② 接口
调用三级知识库（公共 + 部门 + 个人）+ 引用溯源，从已收录文档中精准检索
③ 模型
匹配知识领域、定位相关文档段落，生成结论并附原文链接，支持一键核对原文

交易查不到账
收单与网络支付最高频的一类求助 —— 过去要逐个系统翻
📌 场景是什么
商户最常说的两句话：「钱没到账」「这笔交易失败了」。过去要分别登录收付通、收银宝、查秒到记录、再翻业务规则，来回对口径。
现在一句话提问，跨系统串起来答。
🧵 这个场景是怎么搭起来的 提词 + 接口 + 模型
① 提词
先问清商户号、时间、金额，按「交易状态 → 结算 → 秒到」逐层排查，缺参数就追问
② 接口
实时调收付通（交易查询 / 诊断）与商户侧（结算 / 秒到），用真实数据说话
③ 模型
串起多系统结果、定位卡在哪一环，生成结论并附知识库引用

商户资料变更
入网、资料变更、门店终端、渠道报备 —— 资料散在多个系统
📌 场景是什么
商户入网建档、换结算卡、更新证件、查门店与终端，这些资料分散在系统不同的模块中。
现在一次提问，档案、终端、报备一次看全。
🧵 这个场景是怎么搭起来的 提词 + 接口 + 模型
① 提词
先确认商户身份与要办的事，再按对应流程给材料清单与步骤，不跨事项混答
② 接口
收银宝（商户 / 门店 / 终端、渠道报备）、收付通（商户档案）、结算与套餐余量
③ 模型
判断属于哪一类事项，把分散资料拼成一张视图，给出下一步该做什么

接入联调报错
接口对接、联调报错、报文分析 —— 对应网络支付类业务
📌 场景是什么
商户或渠道接入时，最容易卡在接口报错与联调排障上：报错码看不懂、报文拿不到、文档找不到对应章节。
现在把报错码贴给发仔，直接给排查路径。
🧵 这个场景是怎么搭起来的 提词 + 接口 + 模型
① 提词
先收齐报错码、报文、接口名，按「签名 → 参数 → 报备 / 权限 → 渠道状态」顺序定位
② 接口
收付通（联调日志、原始报文）、收银宝（卡 bin、渠道报备）
③ 模型
读懂报错码与报文，匹配研发智擎技能包与接口文档，给出排查步骤与依据
