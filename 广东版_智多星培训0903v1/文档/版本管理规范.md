> 贵州版规范见 `贵州版_智多星培训0910/文档/版本管理规范.md`。

## 二、每次版本定稿后的归档动作（标准流程）

1. **快照演示稿** → `归档/v<日期>_<版本名>/培训材料.html`
2. **快照讲稿** → 同目录 `培训讲稿.md`
3. **写修订记录** → 同目录 `修订记录.md`（逐条说明页面、内容、原因）
4. **更新核心大纲** → 同目录 `核心大纲.md`，并同步 `文档/核心大纲.md`
5. **更新总索引** → `文档/版本记录.md` 追加版本行与修订明细
6. **保留工作区** → `演示稿/` 继续作为下一轮迭代工作区

## 三、命名规范

> **核心规则：演示文件带「分支前缀」，便于在编辑器标签页 / 文件管理器中一眼区分是哪一版；
> 归档快照不带前缀（已位于带日期的版本目录内，天然唯一）。**

| 类型 | 命名格式 | 示例 |
|------|---------|------|
| 项目目录 | `<分支>_智多星培训<日期>` | `广东版_智多星培训0903v1` |
| 演示稿 | `演示稿/<分支>_演示稿.html` | `演示稿/广东版_演示稿.html` |
| 讲稿 | `演示稿/<分支>_讲稿.md` | `演示稿/广东版_讲稿.md` |
| 版本目录 | `归档/v<YYYYMMDD>_<版本名>` | `归档/v20260903_当前基线` |
| 归档文件 | `<类型>.<ext>`（在版本目录内） | `培训材料.html` |

> 同一天多次定稿时，在版本名后追加序号，如 `v20260903_内容精简2`。

## 四、归档内容清单（每个版本目录必备）

- [ ] `修订记录.md` —— 本次修订条目（页面 / 变更点 / 原因）
- [ ] `核心大纲.md` —— 结构大纲（页面构成、时长、要点）
- [ ] `培训材料.html` —— 定稿的 HTML 演示稿
- [ ] `培训讲稿.md` —— 配套讲稿

---

## 五、版本还原方法

如需回退到某一历史版本：

1. 从 `归档/v<日期>_<版本名>/` 中取出 `培训材料.html`
2. 复制到 `演示稿/广东版_演示稿.html`
3. 同理取出 `培训讲稿.md` 替换 `演示稿/广东版_讲稿.md`

> 注意：HTML 中的图片引用为相对路径 `../素材/`（归档版为 `../../素材/`），还原后需保证 `素材/` 存在。

## 六、修订记录写法约定

每条修订建议包含三要素，便于追溯：

```
| 页面 | 变更点 | 原因/说明 |
|------|--------|----------|
| P7 三级知识库 | 删除安全红线段落 | 评审认为不宜在对外培训中强调 |
```

对于结构性调整（增删页、合并页），需在修订记录中单列说明页面总数变化。
