> 贵州版规范见 `智多星培训0910贵州版/outputs/versions/贵州版_版本管理规范.md`。

## 二、每次版本定稿后的归档动作（标准流程）

1. **快照培训材料** → `versions/v<日期>_<版本名>/广东版_v<日期>_培训材料.html`
2. **快照讲稿** → 同目录 `广东版_v<日期>_培训讲稿.md`
3. **写修订记录** → 同目录 `广东版_v<日期>_修订记录.md`（逐条说明页面、内容、原因）
4. **更新核心大纲** → 同目录 `广东版_v<日期>_核心大纲.md`，并同步 `versions/广东版_核心大纲.md`
5. **更新总索引** → `versions/广东版_版本记录.md` 追加版本行与修订明细
6. **保留工作区** → `outputs/` 继续作为下一轮迭代工作区

## 三、命名规范

> **核心规则：所有材料文件名以「分支前缀」开头，归档快照再带版本号。**
> 目的是避免与贵州版（`智多星培训0910贵州版/`）出现同名文件，无法区分。

| 类型 | 命名格式 | 示例 |
|------|---------|------|
| 分支前缀 | `广东版_` / `贵州版_` | `广东版_核心大纲.md` |
| 版本目录 | `v<YYYYMMDD>_<版本名>` | `v20260903_当前基线` |
| 归档文件 | `<分支前缀>_v<YYYYMMDD>_<类型>.<ext>` | `广东版_v20260903_培训材料.html` |

> 同一天多次定稿时，在版本名后追加序号，如 `v20260903_内容精简2`。

## 四、归档内容清单（每个版本目录必备）

- [ ] `广东版_v<日期>_修订记录.md` —— 本次修订条目（页面 / 变更点 / 原因）
- [ ] `广东版_v<日期>_核心大纲.md` —— 结构大纲（页面构成、时长、要点）
- [ ] `广东版_v<日期>_培训材料.html` —— 定稿的 HTML 演示稿
- [ ] `广东版_v<日期>_培训讲稿.md` —— 配套讲稿

---

## 五、版本还原方法

如需回退到某一历史版本：

1. 从 `outputs/versions/v<日期>_<版本名>/` 中取出 `广东版_v<日期>_培训材料.html`
2. 复制到 `outputs/` 并重命名为 `广东版_通联智多星平台培训_设计稿.html`
3. 同理取出 `广东版_v<日期>_培训讲稿.md` 替换 `outputs/` 下对应讲稿

## 六、修订记录写法约定

每条修订建议包含三要素，便于追溯：

```
| 页面 | 变更点 | 原因/说明 |
|------|--------|----------|
| P7 三级知识库 | 删除安全红线段落 | 评审认为不宜在对外培训中强调 |
```

对于结构性调整（增删页、合并页），需在修订记录中单列说明页面总数变化。
